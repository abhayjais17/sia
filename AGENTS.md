# AGENTS.md: Aqurk

Project guide for coding agents (Codex). Read this fully before changing anything.

## What Aqurk is
An anonymous, end-to-end encrypted, peer-to-peer chat web app. Two people enter the same name + secret code, join the same private room, and chat with no account, email, phone number or database. Tagline: **"Be heard. Not seen."** Supporting line: "End-to-end encrypted, with no accounts or stored data."
Never claim "100% untraceable". Honest wording: "End-to-end encrypted, no accounts, no stored data".

## Current state
- Frontend (Next.js 16 App Router, TypeScript, Tailwind v4, shadcn/base-ui, Framer Motion, sonner) was generated by v0.dev. It runs with `pnpm dev`.
- Everything is **mock**: connection, presence, delivery ticks, crypto, file transfer, calls. Integration points are 4 hooks with `// TODO` markers:
  - `hooks/use-mock-connection.ts` (room join/connect state machine)
  - `hooks/use-chat-connection.ts` (messages, peer, typing, ticks, reactions, delete)
  - `hooks/use-crypto.ts` (key derivation, encrypt/decrypt, safety code)
  - `hooks/use-file-transfer.ts` (chunking, progress)
  - `hooks/use-call.ts` (voice/video calls)
- Known gaps in the UI: no Settings sheet, no `/how-it-works` `/privacy` `/safety` pages, no Report/Block dialog, theme switcher is still a native `<select>` (to be replaced by a hamburger menu), mobile landing layout pushes the form below the fold, landing page is cluttered (trust badges, footer links, preview labels), `next.config.mjs` Permissions-Policy blocks camera and microphone.
- v0 wrote very dense one-line code. Reformat touched files (Prettier) and split long components when you edit them, but do not change behavior while refactoring.

## Product rules (from the PRD)
- Max 2 peers per room. Room is locked after both join. Third peer gets "Room full".
- The raw secret code NEVER leaves the browser. Only a derived room id (hash) goes to the signaling server.
- Server stores nothing: no DB, no logs of IP/room/chat, no analytics, no third-party scripts/CDNs. Room state lives in RAM only and is deleted on disconnect.
- No localStorage/cookies for personal data. Session state is in memory only (tab close = chat gone).
- Light theme is the default. `/chat` is a pure messenger screen (no brand bar/footer).
- Dev-only "Demo controls" must not ship in production builds.
- Demo controls render only when `NEXT_PUBLIC_DEMO=1`. Copy `.env.example` when you need to enable them locally; keep the default value at `0`.

## Target architecture
| Layer | Choice |
|---|---|
| Frontend | This Next.js app (can be static export) on Cloudflare Pages or Vercel |
| Signaling | Cloudflare Worker + Durable Object (WebSocket, one DO per room hash, RAM only) in `/worker` |
| Transport | WebRTC DataChannel (messages, files) + MediaStream (calls) |
| Crypto | Web Crypto API: PBKDF2 (>= 200k iterations, SHA-256) -> HKDF -> room id + AES-256-GCM key. Random 96-bit IV per message |
| NAT traversal | Google public STUN + Cloudflare Realtime TURN (credentials minted by the Worker) |
| Safety code | Hash of both peers' DTLS fingerprints (from SDP), shown as 12 emoji + 5x5 digits. Detects a malicious signaling server |

## Crypto design (follow exactly)
1. `master = PBKDF2(code, salt = "aqurk-v1", 250000, SHA-256, 256 bit)`.
2. `roomId = hex(HKDF(master, info="aqurk-room"))` (sent to server). `key = HKDF(master, info="aqurk-enc")` imported as non-extractable AES-GCM key.
3. Every application message is JSON, encrypted with AES-GCM, random 12-byte IV, sent as `iv || ciphertext`. Never reuse an IV. Optionally bind `additionalData` = message type + id.
4. Safety code = SHA-256 of the two DTLS fingerprints sorted lexicographically, mapped to a fixed 256-emoji table (12 emoji) plus 25 digits.
5. Warn the user about weak codes (existing strength meter). Anyone who guesses the code can join; rate-limit joins per IP on the Worker.

## App-layer protocol (over the encrypted DataChannel)
Message envelope types: `msg`, `ack` (delivered/seen), `typing`, `ping`/`pong` (presence every ~5s), `react`, `delete`, `timer` (disappearing), `file-offer`/`file-accept`/`file-decline`/`file-chunk`/`file-end`/`file-cancel`, `call-*` signalling. Validate every incoming envelope with a schema (e.g. zod) and drop unknown/oversized ones.

## File transfer rules
16 KB chunks, respect `bufferedAmount`/`bufferedAmountLowThreshold` backpressure, receiver must accept first, SHA-256 integrity check at the end, cancel/pause/resume, max 200 MB. Receiver writes via File System Access API streaming where available, StreamSaver-style fallback otherwise; avoid holding the whole file in RAM.

## Working agreements
- On Windows, always write files as UTF-8 WITHOUT BOM (never PowerShell Set-Content/Out-File defaults). Edit JSON/config files with proper tools, not by rewriting them via shell redirection.
- Work in small steps. After each step: run `pnpm typecheck` and `pnpm build`, fix errors, then `git commit` with a clear message. Never leave the app broken.
- Keep UI components free of transport/crypto logic; all of it goes through the 5 hooks above (keep their public return shapes stable so the UI keeps working).
- Add tests for pure logic (crypto, protocol parsing, chunking, safety code) with Vitest.
- Security first: no `eval`, no `dangerouslySetInnerHTML` with message content, sanitize/escape everything from the peer, strict CSP, pinned dependencies.
- Do not add analytics, trackers, third-party fonts/CDNs, or any storage of personal data.
- If a requirement is ambiguous, pick the simplest option that follows the rules above and note it in the final summary.
